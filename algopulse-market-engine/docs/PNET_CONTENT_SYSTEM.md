# PNET Content System

Purpose: create a reusable 30-day content system for ProfitNet / PNET that emphasizes transparency, verified contribution, real-world utility, and evidence. This is internal/public-ready copy scaffolding only. Publish nothing externally without human review.

## Content Principles

- Lead with utility, not price.
- Show evidence, not hype.
- Treat contribution credits as access/workflow credits, not financial rewards.
- Treat real earning levers as evidence-backed operating experiments, not guaranteed income.
- Use screenshots, receipts, hashes, and docs links only after redaction review.
- Do not use buy/sell, moon, ROI, yield, guaranteed income, passive income, or exchange-listing language.
- Do not use live market, liquidity, holder, or earnings numbers unless verified from current sources immediately before publication.

## Content Pillars

| Pillar | Message | Evidence to attach | Avoid |
| --- | --- | --- | --- |
| Utility | PNET helps unlock delayed market intelligence, contribution credits, and bounded beta access. | Dashboard screenshots, API docs, contribution receipts. | Trading/profit promises. |
| Verified contribution | Contributors can submit docs fixes, pool observations, bug reports, demo feedback, and data-source ideas for manual review. | Contribution Protocol screenshots and pending-review receipts. | Automatic rewards or pay-to-govern framing. |
| Real-world operating evidence | ProfitNet can document real operating levers such as mining/bandwidth/research experiments when independently verified. | Redacted receipts, dated logs, methodology notes. | Guaranteed earnings, advice, or extrapolated income claims. |
| Transparency | The repo documents what is built, blocked, audited, unaudited, local, TestNet, or Mainnet. | GitHub docs, tests, gate logs, audit-readiness checklist. | "Audited", "CEX ready", or "production ready" without proof. |
| Community learning | Show how builders can test, review, contribute, and improve the system. | Issues, PRs, screenshots, docs deltas. | Artificial activity or engagement farming. |

## X Thread Templates

### Thread 1: What PNET Does

1. PNET is being built as a utility layer for ProfitNet/AlgoPulse workflows: delayed market intelligence, contribution credits, report access, and transparent evidence.
2. The current focus is not price. It is usefulness: can a user inspect data, contribute evidence, spend credits, and understand what is blocked?
3. The Access dashboard shows credits, contribution submissions, and bounded unlocks.
4. Credits are not token rewards, revenue share, staking, or governance power.
5. The repo documents what is local, TestNet, blocked, unaudited, or waiting for review.
6. The goal is simple: build utility people can verify.
7. Read the docs and challenge the assumptions.

### Thread 2: Contribution Protocol

1. We added a Contribution Protocol beta for PNET.
2. Users can submit docs improvements, pool observations, bug reports, demo feedback, or data-source suggestions.
3. Submissions enter manual review. Nothing is auto-paid.
4. Credits can unlock bounded access like delayed reports, pair scans, paper simulations, non-binding comments, or AlgoFlow previews.
5. Credits do not unlock trading, treasury control, token payouts, or binding governance.
6. This is how we want community momentum to work: contribution first, receipts second, claims last.

### Thread 3: Real Earnings, Carefully

1. ProfitNet is tracking real-world operating experiments carefully.
2. If we talk about income levers like mining or bandwidth sharing, we will use verified receipts and methodology, not hype.
3. No earnings claim should be posted without date, source, redaction, and context.
4. Past receipts do not imply future income.
5. The content standard is: show what happened, how it was measured, and what risks remain.
6. Utility plus transparency beats vague promises.

### Thread 4: x402 And Paid Reports

1. The x402 workstream proves a narrow idea: payment-gated access to delayed/redacted market intelligence.
2. It does not trigger trades.
3. It does not expose fresh executable routes.
4. It does not custody funds or give signer access.
5. The useful product is paid access to safe reports and verification summaries.
6. Gate docs explain what is complete, what is TestNet-only, and what remains blocked before Mainnet.

### Thread 5: No-Hype Tokenomics

1. PNET tokenomics should be documented as facts, not promises.
2. Public copy should include the ASA ID, utility boundaries, and safety notes.
3. It should not include price targets, guaranteed returns, listing hints, or buy/sell language.
4. Utility surfaces today: report access, contribution credits, delayed intelligence, and evidence workflows.
5. Anything beyond that needs verification and review.
6. The strongest narrative is not "trust us." It is "verify the work."

## Blog Post Templates

### Blog 1: Building PNET Around Verifiable Utility

**Title:** Building PNET Around Verifiable Utility

**Opening:** PNET is being developed as a utility layer for ProfitNet and AlgoPulse workflows. The goal is not to make unsupported market claims. The goal is to make useful access, contribution, and reporting flows that can be verified.

**Sections:**

1. What exists today
2. What credits unlock
3. What credits do not unlock
4. How contribution review works
5. How transparency receipts reduce ambiguity
6. What remains blocked

**Close:** This is beta infrastructure. Review the docs, test the flows, and challenge the evidence.

### Blog 2: Contribution Credits Without Pay-To-Govern

**Title:** Contribution Credits Without Pay-To-Govern

**Opening:** Contribution systems can go wrong when payments become power. PNET credits are designed as bounded access receipts, not governance control.

**Sections:**

1. Why manual review matters
2. Valid contribution categories
3. Credit spend boundaries
4. Non-binding governance signals
5. What a future contract would need to prove
6. Abuse and spam controls still needed

**Close:** Good governance starts with clean boundaries.

### Blog 3: How We Talk About Real Earnings

**Title:** How ProfitNet Talks About Real Earnings

**Opening:** Real-world earning experiments can be useful, but only if documented carefully. ProfitNet should show receipts and methodology, not promises.

**Sections:**

1. What counts as evidence
2. How receipts are redacted
3. Why live numbers need source checks
4. What cannot be claimed
5. How this connects to contribution and transparency

**Close:** The standard is evidence first, interpretation second.

- [ ] Does it avoid secrets, payment payloads, wallet material, and fresh executable routes?
- [ ] Does it distinguish local, TestNet, Mainnet, mock, and delayed data?
- [ ] Does Rob approve the exact wording?
